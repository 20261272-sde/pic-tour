# Pic-Tour 초안

사진 선택으로 여행 취향을 발견하고, 여행지를 추천한 뒤 초대장을 공유하는 웹 프로토타입입니다.

## 실행 방법
### VS Code Live Server (권장)
1. VS Code 확장 프로그램에서 `Live Server`(Ritwick Dey)를 설치합니다.
2. VS Code에서 `파일 > 폴더 열기`로 `pic-tour-draft` 폴더 자체를 엽니다. (상위 폴더를 열면 주소 경로가 달라집니다.)
3. `index.html`을 우클릭 → `Open with Live Server`를 선택하거나, 하단 상태 표시줄의 `Go Live`를 누릅니다.
4. 브라우저에서 `http://127.0.0.1:5500/index.html`이 열리면 `내 여행 취향 발견하기`를 눌러 테스트합니다.

Live Server로 열면 파일을 저장할 때마다 자동으로 새로고침되고, `초대 링크 복사`(클립보드 API)도 정상 동작합니다.

### 파일로 직접 열기
`index.html`을 Chrome 또는 Edge에서 바로 열어도 동작하지만, 브라우저에 따라 초대 링크 복사가 막힐 수 있습니다.

이미지 저장 기능은 html2canvas CDN을 사용하므로 인터넷 연결이 필요합니다. 나머지 테스트 흐름은 로컬에서 실행할 수 있습니다.

## 무료 웹사이트로 배포 (GitHub Pages)
AI·API·서버 없이 정적 파일만으로 동작하므로 GitHub Pages에 그대로 올리면 됩니다.

1. GitHub에서 새 저장소(New repository)를 **Public**으로 만듭니다. (예: `pic-tour`)
2. 저장소 화면의 `uploading an existing file` 링크를 누르고 아래 항목을 드래그해 올린 뒤 `Commit changes`를 누릅니다.
   - `index.html`, `app.js`, `data.js`, `styles.css`, `README.md`, `.nojekyll`
   - `images` 폴더 (폴더째 드래그)
   - 루트에 있는 한글 이름 원본 JPG들은 올리지 않아도 됩니다. (사이트는 `images/` 폴더만 사용)
3. 저장소 `Settings > Pages`에서 Source를 `Deploy from a branch`, Branch를 `main` / `/ (root)`로 선택하고 Save.
4. 1~2분 뒤 `https://<GitHub아이디>.github.io/pic-tour/` 주소로 접속할 수 있습니다.

내용을 고친 뒤에는 바뀐 파일만 같은 방법으로 다시 올리면(덮어쓰기) 자동으로 사이트에 반영됩니다.

## 수정할 곳
- `data.js`: 질문(라운드), 선택지, 사진 크롭 위치(`pos`/`zoom`), 취향 유형, 여행지·코스·팁
- `images/`: 사진 파일 (콘텐츠랩 원본을 영문 파일명으로 복사해 사용)
- `styles.css`: 색상(`:root` 변수), 글꼴, 배치
- `app.js`: 점수 계산, 최종 택1 후보 산정, 티켓·공유·친구 비교

## 사진 추가 방법
1. 사진을 `images/`에 영문 파일명으로 넣습니다. (예: `images/haeundae.jpg`)
2. `data.js`의 `images`에 항목을 추가합니다.
   - `kinds`: 풍경 분류 (`green` 숲 · `sea` 바다 · `mountain` 산 · `heritage` 전통 · `city` 도시 · `night` 야경 · `field` 들판 · `lake` 호수 · `art` 예술 · `village` 마을). 한 화면에는 분류가 겹치지 않는 사진만 함께 나옵니다.
   - `tone`: 대표 색감 (`green` · `blue` · `warm` 붉은/주황/금빛 · `pink` · `pastel` · `white` · `night`). 한 화면에는 색감도 겹치지 않게 나옵니다. (단풍 여러 장, 노을 여러 장 방지)
   - `views`: 이 사진을 어떤 질문 주제(`t`)에 어떤 문구로 쓸지. `pos`(보여줄 위치), `zoom`(확대)으로 질문에 맞는 부분만 잘라 보여줄 수 있습니다.
3. 새 여행지는 `destinations`에 추가하면 최종 택1 후보와 티켓에 자동 반영됩니다.

## 질문 출제 방식
- 사진 질문 은행 8개 주제(길·색·장면·한 장면·소리·쉼·창밖·계절) 중 매번 4개를 무작위 출제하고, 직전 회차에 나온 주제는 피합니다. (브라우저 localStorage에 직전 회차 기록)
- 시간대·동행·일정 질문은 매번 나오지만 질문 문장은 여러 버전 중 무작위입니다.
- 각 질문의 사진 조합도 매번 무작위이며, 앞 라운드에 나온 사진은 되도록 다시 쓰지 않습니다.

## 흐름
1. 사진/무드 카드 7라운드 (질문 은행에서 무작위 출제)
2. 최종 라운드: 취향과 가장 가까운 여행지 3곳 중 **1곳 택1**
3. 탑승권 발권: 목적지·취향 유형·탑승 시간·동행·일정 스타일·일치도, 이름 입력, PNG 저장
4. 여행 고민 덜어주기: 추천 하루 코스, 추천 시간·준비물, 일정/동행별 팁
5. 초대 링크 공유 → 친구가 참여하면 취향 일치도, 둘이 함께 가기 좋은 곳, 일정 조율 팁 표시

## 현재 범위와 한계
- 7가지 취향 유형(숲결 산책자 · 윤슬 자유인 · 시간 수집가 · 감성 발견가 · 도시 낭만가 · 새벽 능선가 · 초원 소풍가), 여행지 17곳, 사진 25장
- 촬영지가 특정되지 않은 사진(목장의 저녁, 다원의 아침, 명상정원, 철쭉, 세상을 여는 빛)은 질문에만 쓰고 여행지로는 넣지 않았습니다.
- `seoul-dawn.jpg`, `tea-field.jpg`는 원본 가운데 워터마크가 있어 아래쪽만 잘라 사용합니다.
- 점수는 선택지별 가중치 합산 + 코사인 유사도로 계산 (AI·외부 API 없음)
- 초대 링크에 이름·취향 점수·목적지·스타일을 담아 전달 (서버 저장 없음)
- 로그인, 데이터베이스, 실시간 공동 테스트, 방문 기록 저장은 구현하지 않았습니다.
- 기본 관광지명과 설명은 교체용 예시입니다. 실제 출품 전 한국관광콘텐츠랩 사진의 촬영지/출처/이용 조건을 확인해 실제 정보로 바꿔야 합니다.
- 사진 선택 결과는 심리검사나 성격 진단이 아니라 여행 선호를 탐색하는 가벼운 콘텐츠입니다.

## 주의
콘텐츠랩 사진을 서비스에 넣기 전에 다운로드, 저장, 웹 게시, 편집, 초대장 이미지 내 재사용이 허용되는지 해당 콘텐츠의 이용 조건을 확인하세요. API를 호출하지 않는 것과 이미지 재사용 권한은 별개의 문제입니다.
